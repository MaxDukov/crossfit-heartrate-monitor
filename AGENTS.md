# Project Rules — CF-Monitor

## Дизайн-документация

При любых изменениях в `docs/design/UI/` (новые макеты, правки существующих, удаление) — **всегда** обновлять `docs/design/UI/README.md` в том же коммите. README — единый каталог всех UI-макетов с описанием каждой версии.

## Проверка после изменений

После внесения изменений всегда проверять минимальную доступность фронтенда и бэкенда. В проверку бэкенда включать проверку работоспособности базы данных.

## Pylint перед PR

**ВСЕГДА** перед созданием PR локально прогонять pylint и предлагать исправить выявленные ошибки:

```bash
cd backend && .venv/bin/python -m pylint app --recursive=y
```

Найденные ошибки — обсудить с пользователем: исправить реальные проблемы кода, шум (фреймворковые паттерны) — отключить в `.pylintrc`.
