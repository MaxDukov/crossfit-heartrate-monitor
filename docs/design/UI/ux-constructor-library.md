# UX-исследование: Конструктор и Библиотека (страница /wod)

> Дата: 13.09.2026 (дополнено в тот же день разделами 1а–1в: процесс создания тренировки, CRUD-матрица, поэкранная оценка).
> Критерии оценки: (1) минимизация шагов в основных сценариях — поиск / выбор / редактирование; (2) единообразие стиля и методов взаимодействия между экранами.
> Метод: разбор кода frontend и backend (факты с file:line), без пользовательских сессий.

## 1а. Процесс создания тренировки (end-to-end)

Тренерский путь «нужна тренировка → она запущена на мониторе»:

| Шаг | Вкладка | Что делает тренер | Что получается |
|---|---|---|---|
| 0 | Инвентарь | заведение инвентаря зала (штанга, кольца,…) | справочник `Equipment` |
| 1 | Движения | заведение упражнений с признаками (модальность, мышцы, сложность, темы, инвентарь) | каталог `Movement` |
| 2 | Конструктор | сборка: протокол/длительность/интенсивность/тема/имя/описание + строки упражнений | черновик шаблона |
| 3 | Библиотека | проверка результата, правка, удаление/архивация | шаблон `WodTemplate` |
| 4 | Планирование / Быстрый выбор | назначение на слоты цикла либо разовый запуск | тренировка в зале |

Вкладки физически независимы: на любом шаге можно уйти в соседнюю и потерять контекст (введённые параметры конструктора не сохраняются при переходе).

## 1б. CRUD-матрица по экранам

| Экран | Create | Read (поиск/просмотр) | Update | Delete |
|---|---|---|---|---|
| Инвентарь | форма | список | ? | ? |
| Движения | модалка «+ Новое движение» | **только текстовый поиск по имени/ключу**; просмотр = редактор | та же модалка | inline-confirm в модалке |
| Конструктор | сохранение в библиотеку | подбор движения: автокомплит по имени **или** пикер «Каталог…» (поиск + фильтры-чипы) | правка полей/строк инлайн | удаление строки, без подтверждения |
| Библиотека | — (создание только через Конструктор) | карточки; **фильтры: search по имени + `<select>` темы**; превью нет — просмотр = редактор | делегирует Конструктору (3+ клика) | confirm() → архивация либо удаление, restore |
| Планирование | цикл/слоты | карточки циклов | слоты | confirm() цикла |

Легенда к «Read не только по имени»:

- **Конструктор** (после правки от 13.09, ветка `wod-ui-redesign`): пикер фильтрует движения по 5 группам атрибутов — эталон в этой странице.
- **Библиотека**: атрибуты шаблона (формат, интенсивность, длительность) показаны на карточке, но **не фильтруются**; сервер (`backend-go/internal/handlers/wods.go:237-253`) поддерживает только `theme` и `search` по имени.
- **Движения**: атрибуты показаны текстом в строке, не фильтруются; в модалке редактора те же атрибуты — чипы.

## 1в. Поэкранная оценка удобства

**Инвентарь** — вспомогательный, трение низкое.

**Движения** — Create/Update/D в одном модальном окне — быстро (2 клика до формы). Read — слабое место: при каталоге 100+ движений найти «все тяжелоатлетические на ноги» невозможно (только листать или знать имя). Признаки, которые тренер старательно заполняет при создании, недоступны для поиска.

**Конструктор** — создание тренировки из известных имён — быстро (автокомплит). Сборка по смыслу («что-то на ноги без штанги») — теперь возможна через пикер. Слабые места: выбор темы — чипы (хорошо), но выбор формата/интенсивности — `<select>` рядом (два разных механизма в одной форме); смена выбранного упражнения = стереть текст; строки без выбора молча теряются.

**Библиотека** — главный разрыв сценария: тренировка создана и ушла в каталог, где её **нельзя найти по смыслу** — только по имени или теме. Тема фильтруется `<select>`'ом, тогда как в Конструкторе та же тема — чипы: один и тот же справочник в двух разных механизмах на соседних вкладках. Формат («силовая» vs «AMRAP» — фактический тип нагрузки), интенсивность и длительность не фильтруются вовсе (и на бэке тоже). Просмотр = редактирование (случайный клик открывает форму).

**Планирование** — вне фокуса этого документа, паттерн confirm() отличается от остальных.

## 1г. Вывод: что унифицировать

1. Один механизм выбора значения справочника — **чипы** (как тема в Конструкторе и атрибуты в пикере): заменить `<select>` темы в Библиотеке; формат/интенсивность в Конструкторе тоже чипами.
2. Фильтр-бар списков «поиск + чипы» на Библиотеке (тема/формат/интенсивность) и в Движениях (модальность/мышцы/сложность/темы/инвентарь).
3. Серверная поддержка: расширить `ListWodTemplates` параметрами `format`, `intensity` (тривиально, тот же WHERE-паттерн).

## 2. Основные сценарии — фактические шаги

### 2.1. Поиск упражнения

| Экран | Механизм | Где |
|---|---|---|
| Конструктор | substring-автокомплит в строке, клиентский, мгновенный, лимит 6 подсказок, без клавиатуры | Constructor.tsx:72-78, 211-232 |
| Библиотека (шаблоны) | серверный поиск, debounce 250 мс, deep-link `?search=` | TemplatesLibrary.tsx:25,30-33; WodPage.tsx:41-42 |
| Движения | клиентский substring по полному списку, мгновенный, без debounce | MovementsCatalog.tsx:36-39 |

**Три разных метода поиска на трёх вкладках одной страницы.** API умеет серверный поиск движений (`api.ts:217-218`), но не используется.

### 2.2. Фильтрация

| Экран | Фильтры | Реализация | Состояние |
|---|---|---|---|
| Конструктор | фильтров выбора упражнения **нет** (только параметры тренировки) | — | useState |
| Библиотека | 1 фильтр «Все темы» | нативный `<select>` | useState, серверный |
| Движения | фильтров нет (только поиск) | — | useState |

Пример расхождения: подбор упражнения в конструкторе — только текстовый автокомплит; по теме/мышцам/инвентарю отобрать нельзя ни в одной вкладке-списке (чипы атрибутов есть только внутри модалки редактора движения, MovementsCatalog.tsx:234-291). Фильтры не сохраняются: уход со вкладки сбрасывает всё (в URL пишется только одноразовый `search` библиотеки).

### 2.3. Выбор (добавление в тренировку)

Единственный путь — автокомплит в строке конструктора: «+ строка» → печатать → клик по подсказке (~2 действия). Браузинга нет: неизвестное имя не подобрать; кнопки «добавить из каталога» нет; вкладка «Движения» не умеет «добавить в тренировку» (клик открывает редактор, MovementsCatalog.tsx:78-80). Строки без выбранного `movement_key` молча отбрасываются при сохранении (Constructor.tsx:94).

### 2.4. Редактирование

| Сущность | Путь | Шаги |
|---|---|---|
| Шаблон | Библиотека → клик карточки → автопереход на вкладку Конструктор → правка → «Сохранить изменения» → «К библиотеке» вручную | 3+ клика + правки, без авто-возврата (Constructor.tsx:293-302) |
| Движение | Движения → клик строки → модалка → правка → «Сохранить» | 2 клика |
| Движение внутри шаблона | Движения → модалка → ссылка «используется в шаблонах» → Библиотека → карточка → Конструктор | ~5-6 кликов |

Просмотра/превью нет нигде: любой клик по элементу каталога = открытие формы редактирования (случайный клик приводит к редактору).

### 2.5. Удаление — три паттерна

| Объект | Паттерн | Где |
|---|---|---|
| Шаблон | браузерный `confirm()` | TemplatesLibrary.tsx:38 |
| Цикл | браузерный `confirm()` | WodPage.tsx:94 |
| Движение | inline-confirm внутри модалки | MovementsCatalog.tsx:338-359 |
| Строка упражнения в конструкторе | без подтверждения, красный «✕» | Constructor.tsx:255-262 |

## 4. Оценка по критериям

**Минимизация шагов — узкие места:**
1. Подбор упражнения без известного имени: невозможен из конструктора (обход через вкладку «Движения» и запоминание названия) — главный издержка сценария сборки тренировки.
2. Круг правки шаблона: 3 клика + ручной «К библиотеке»; правка движения внутри шаблона — до 6 кликов.
3. Смена выбранного упражнения требует стирания текста (Constructor.tsx:215 сбрасывает movement_key), отдельной кнопки «очистить/сменить» нет.
4. Нет превью: «посмотреть» = «открыть редактор».

**Единообразие — расхождения:** три метода поиска, отсутствие единого фильтр-компонента (и самих фильтров в списках), два механизма подтверждения удаления (+ один сценарий без подтверждения), редактирование вкладкой vs модалкой, список vs карточки. Базовые стили (primary emerald-600, красный destructive, цветные баннеры) при этом согласованы.

**Что работает хорошо:** мгновенная клиентская фильтрация движений (список предзагружен), inline-confirm движения с перечислением ссылающихся шаблонов (MovementsCatalog.tsx:318-336), архивация вместо жёсткого удаления шаблонов, empty states везде.

## 5. Рекомендации (приоритет по влиянию на шаги)

1. **Единый пикер упражнений** (shared-компонент: поиск + фильтры-чипы по модальности/мышцам/сложности/темам/инвентарю + кнопка «+») — используется и в конструкторе, и как будущий фильтр каталога движений. Закрывает: браузинг, единообразие поиска/фильтров, «добавить из каталога».
2. **Общий фильтр-бар** для списков (поиск + чипы) на Библиотеке и Движениях; серверный поиск + debounce как единый метод (API уже готов).
3. **Сохранение фильтров в URL** (`?tab=&search=&theme=…`) для всех вкладок — глубокие ссылки уже частично работают.
4. **Авто-возврат в Библиотеку после сохранения шаблона** (или toast с undo) вместо ручной кнопки.
5. **Единый паттерн подтверждения удаления** (inline-confirm) и превью/детали по клику с отдельной кнопкой правки.
6. Заменить `window.location.href` на `navigate()`; вынести `chip()`-классы и фильтрацию по имени в общие утилиты.
